# 目录说明

这个工作区里有**三套代码**（旧版两套 + 新版一套），以及调研资料和运行时数据。
这份文件说清楚谁是谁、哪些能动。

---

## 一、代码（入库）

```
workbuddy_api/        旧版网关（Node.js，约 11000 行）
                      ★ 当前打包用的源
                      ★ 路径被 WorkBuddyPanel/build.ps1 硬编码
                      ★ 已装面板的 settings.json 也指向这里
                      → 不要改名、不要移动

WorkBuddyPanel/       旧版面板（WPF）
                      ★ 打包入口在这（make-installer.ps1）
                      → 不要改名、不要移动

next/                 新版（全 .NET，做了一半）
                      网关 = ASP.NET Core，界面 = WPF-UI
                      和上面两套并行开发、互不影响
                      入口：docs/HANDOVER.md
```

### 两套的关系

| | 旧版（现在能用） | 新版（在建） |
|---|---|---|
| 网关 | Node.js | ASP.NET Core |
| 界面 | WPF 手写 XAML（1733 行单文件） | WPF-UI 4.3 + MVVM Toolkit |
| 运行时 | 两个（Node + .NET） | 一个 |
| 打包体积 | 230 MB → 70 MB | 未测 |
| 测试 | Core 110 项 + 网关 300+ 项 | 五套测试项目 |

**旧版继续可用、继续打包。** 新版成熟了再切，切换前旧版一行不动。

## 七、⛔ 别做的事

### 1. 别杀 `127.0.0.1:8787` 上的 node 进程

```
那是 AI 助手（pi）的模型来源 —— 杀了助手当场断线
也是 DSH 的模型来源 —— 杀了 DSH 团队一起断

查：curl -s http://127.0.0.1:8787/healthz
```

### 2. 别改 `D:\BuddyDeck\` 下的文件

```
那是装好的版本。改它：
  · 下次装包会被覆盖，白改
  · 可能让正在跑的面板行为异常

正确做法：改 D:\workfandaiapi 里的源，重新打包，装新包
```

### 3. 别删 `_newapi\one-api.db`

那是 new-api 的全部配置数据（渠道、令牌、用户）。删了要重新配。

### 4. 别删 `%USERPROFILE%\.workbuddy-api\accounts.cn.json`

那是所有 WorkBuddy 账号的保险库。删了要一个个重新导入。

### 5. 别移动 `workbuddy_api/` 和 `WorkBuddyPanel/`

```
WorkBuddyPanel/build.ps1:35   硬编码 Join-Path $parent "workbuddy_api"
已装面板 settings.json         ApiDirectory 指向 D:\workfandaiapi\workbuddy_api
```

移动这两个目录会同时打断打包和已装的面板。
