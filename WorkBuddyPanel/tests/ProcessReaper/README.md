# ProcessReaper 测试

测 `Services/ProcessReaper.cs` —— 那段**会杀进程**的代码。

## 为什么单独一个测试项目

产品代码引 WPF，这个测试引不了（也不想为了测试把 WPF 拖进来）。
所以这里**复制**了那份匹配逻辑，验证判据本身。

⚠ 复制意味着可能不同步。改产品那份的逻辑时，这里也要改。
（两边不一致时以产品为准 —— 这个测试的目的是验证判据思路，
不是替代真实调用。）

## 测什么

场景是真实发生过的：

```
8787 上跑着几小时前启动的网关（孤儿进程）。
代码改了好几轮，但那个进程不会自动重载，它还在跑旧的。
用户重启面板 → 面板看到「端口上有人在监听」→ 采用它
→ 功能还是旧的。用户看到的是「视频还是生成不了」。
```

测试跑完整的五步：

1. **探测** —— 目标端口上有没有人监听、认不认得出是我们的网关
2. **判断** —— 它自报的 buildId 和磁盘上的代码指纹是否一致
3. **重启** —— 停掉旧的、端口是否释放
4. **起新的** —— 新网关自报的指纹是否等于磁盘上的
5. **命脉完好** —— 8787 上那个网关（AI 助手的模型来源）没被误碰

## 怎么跑

```bash
cd tests/ProcessReaper
dotnet run
```

⚠ **它会真的起/停一个测试网关（端口 18798）。**
不会碰 8787 —— 那是 AI 助手的命脉，测试里只做只读探测。

如果 18798 上有别的东西，先改 `Program.cs` 里的 `Port`。

## 退出码

0 = 全过，1 = 有失败。
